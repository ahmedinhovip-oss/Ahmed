## D4 — 根因（核心：展示多状态循环）

```
Agent: [S1 - 选择6M方向：机+料+测]

D3围堵已完成（五个窗口均已冻结/拦截）。现在进入D4根因—这是8D最关键的一步。

我先从三个最有希望的方向开始：
机：回流焊温度曲线有没有异常？最近设备维护记录？
料：USB连接器来料批次有没有变更？供应商有没有同期问题？
测：FCT的USB检测逻辑是什么？能不能检出间歇性故障？

用户: 
- 机：上月换了回流炉热电偶，换后没重新跑温度曲线。查记录发现换后第一批产品峰值温度比标准高8°C。
- 料：来料检验记录正常。
- 测：FCT只测空载电压，不测负载。换负载后回测故障品，30%可复现。

Agent: [S2 - 第一性原理深入]

"这个发现很关键。我先追问物理机制：峰值温度高8°C，对USB连接器焊点意味着什么？从焊接冶金学角度，温度过高会导致什么—IMC层过厚？焊料氧化？润湿不良？有没有人看过焊点截面或做过切片分析？"

用户: 还没做切片。但QA观察了5台故障品的USB焊点，其中3台能看到明显裂纹，位置都在USB连接器的中间两个引脚。正常品没有裂纹。

Agent: [S3 - 反事实挑战]

"好的。现在让我反向挑战这个结论。如果温度过高是根因：

1. 为什么同一块板上其他焊点（HDMI、DC Jack）没有出现裂纹？它们也经过同一个回流炉。
2. 为什么只有中间两个引脚有裂纹？USB连接器通常有4个引脚+2个固定脚—为什么固定脚也没裂纹？
3. 有没有批次在温度正常的情况下也有USB输出问题？比如6月前那台维修记录—那时候还没换热电偶。"

用户: 
1. USB连接器比HDMI/DC Jack重，固定脚焊盘面积也比USB信号引脚大。
2. 中间两个引脚正好在连接器重心下方，插拔时承受最大应力。
3. 6月前那台...查不到当时温度曲线数据了，但热电偶确实是6月初换的。

Agent: [S2 - 再次深入，物理机制]

"我们现在有两个机理线索：
1. 温度过高→焊点可能IMC过厚→脆性增加→插拔/振动后开裂
2. USB连接器较重+中间引脚受力集中→应力集中在脆弱的焊点上

如果这两个因素缺一个，问题还会发生吗？就是说—如果温度正常（焊点延展性好），连接器重+引脚受力集中会不会导致失效？反过来—如果连接器设计更轻/受力更均匀，温度偏高会不会导致失效？这是区分主要原因和促进因素的关键。"

用户: 问了设计部。他们说USB连接器选型时评估过重量对焊点应力的影响，计算结论是"正常焊点强度余量3倍以上"。所以如果焊点正常，不应该裂。但前提是焊点正常。

Agent: [S3 - 再次反事实]

"那追问一个关键反事实：有没有办法让温度偏高的焊点也正常？就是—如果峰值温度高8°C但焊点仍然可靠，是不是温度曲线就不是根因了？比如如果冷却速率合适、或者焊膏成分不同，高温不一定导致开裂？"

用户: 我们拿了同批次的5台未使用产品（库存围堵品），送去做了切片。结果显示USB中间引脚的IMC厚度是7-10μm，正常范围是1-3μm。IMC过厚确实导致焊点脆化。材料工程师确认：峰值温度过高+冷却段速率偏慢共同导致了IMC异常增厚。

Agent: [S2 - MRC追问]

"技术根因已经清楚了。现在追问管理根因。为什么换了热电偶之后没有人验证温度曲线？

- 维护SOP里写了更换热电偶后要验证温度曲线吗？
- 如果写了，为什么没执行？如果没写，当初编写SOP时为什么没把这个步骤写进去？
- 设备维护团队知道热电偶更换会影响温度曲线吗？他们有没有接受过相关培训？"

用户: 
- SOP里没有这个步骤。当初编写SOP时参照的是设备厂家的通用维护手册，厂家手册也没强调这个。
- 维护团队凭经验知道换热电偶可能影响温度，但没有强制验证的流程。
- 更深一层：工厂的变更管理流程要求"关键设备参数变更需验证"，但热电偶更换被定义为"备件更换"而非"参数变更"，所以没触发验证要求。

Agent: [S4 - 综合评分]

📊 D4 根因分析评分：Excellent 🌟
+ TRC完整：温度过高+冷却偏慢→IMC过厚→焊点脆化→应力下开裂
+ 物理机制有切片数据支撑（IMC 7-10μm vs 正常1-3μm）
+ 反事实挑战通过（连接器受力集中是促进因素，不是独立根因）
+ Escape Point完整：FCT未测负载，30%可复现间歇性故障
+ MRC完整：SOP缺失→变更管理分类漏洞→培训不足
+ 多角度探索：6M+断面分析+设计评审+反事实
```

## 本示例展示的关键 v0.2.0 机制

1. **S1→S2→S3→S4 循环**：D4执行了两轮S2→S3循环（物理机制→反事实→再深入→再反事实），直到找到IMC厚度的切片证据
2. **反事实挑战**：D4中追问"如果连接器更轻，高温还会不会导致失效"，区分了主要原因和促进因素
3. **评分驱动迭代**：D5措施1被指出Poka-Yoke等级低（减轻），推动了长期升级计划
4. **MRC双轨**：技术根因追到IMC物理层，管理根因追到变更管理分类漏洞
5. **第一性原理**：D4追问到焊接冶金学物理机制，不满足于"温度过高导致焊点不良"
