## 二、发现的问题

### 🔴 P0 — 必须修

#### 1. 版本号不一致（6 处）

| 文件 | 当前版本 | 应为 |
|------|---------|------|
| `SKILL.md` YAML | `version: 0.2.0` | `0.2.1` |
| `SKILL.md` 标题 | `v0.2.0` | `v0.2.1` |
| `constraints.txt` | `v0.2.0` | `v0.2.1` |
| `gates.md` 标题 | `v0.2.0` | `v0.2.1` |
| `deliverables.md` 标题 | `v0.2.0` | `v0.2.1` |
| `llms.txt` | "56 markdown files" | "~90 markdown files" |

#### 2. constraints.txt 过时

- 没提 `quality-methodologies.md`
- 没提 ISO 9001 profile
- 没提 v0.2.1 四个增强机制（时间模式/贝叶斯/TRIZ/时限感知）
- 读文件顺序与 SKILL.md 矛盾：`constraints.txt` 说先 SKILL 再 AGENTS 再 constraints，但 `SKILL.md` 说先 constraints 再 AGENTS 再 quality-methodologies

#### 3. Gate 规则三地分存

Agent 需要查三个地方才能确认 gate 条件：
- `docs/gates.md` — 基础 gate（评分阻断 + 每 D 的具体条件）
- `SKILL.md` — "不可跳过规则"（7 条，是 gates.md 的简化子集）
- `profiles/iso9001/overlay.md` — ISO 9001 Hard Gates（23 条）
- `profiles/iatf16949/overlay.md` — IATF **没有** hard gates 段

如果 ISO 9001 和 IATF 16949 同时加载，Agent 需要合并三个来源的 gate 条件，容易遗漏。

### 🟡 P1 — 应该修

#### 4. AGENTS.md 和 quality-methodologies.md 的方法论摘要重复

`AGENTS.md` 第 12-54 行（"默认思维框架"章节）是 `quality-methodologies.md` 的 8 行摘要。但 `quality-methodologies.md` 本身就是 Agent 默认要读的文件。AGENTS.md 里这 8 行摘要既不完整（没有 CAPA 三级定义、统计样本量标准、SIPOC 模式等核心执行细节），又占据了 AGENTS.md 的开篇位置。

**建议**：AGENTS.md 的开篇只保留一句"Agent 的默认思维框架由 `docs/methodology/quality-methodologies.md` 定义，在此不重复"。把开篇空间留给 AGENTS.md 的核心职能：操作层面（五状态、方向矩阵、信号、增强机制）。

#### 5. AGENTS.md 的方向矩阵和 methodology/dX.md 的方向矩阵重复

每个 `methodology/dX.md` 都有探索方向矩阵（含方向名称和示例问题）。AGENTS.md 也有一个简化版的探索方向矩阵（含方向名称和关键问题）。两者不完全一致——AGENTS.md 的版本更简洁，methodology 的版本更详细。Agent 两个都读，可能产生混淆。

#### 6. Profile 结构不对称

| 特性 | IATF 16949 | ISO 9001 |
|------|-----------|----------|
| SKILL.md | ✅ | ✅ |
| README.md | ✅ | ✅ |
| overlay.md（叠加表） | ✅ | ✅ |
| overlay.md（Hard Gates） | ❌ | ✅ |
| overlay.md（证据标准） | ❌ | ✅ |
| overlay.md（审计就绪） | ❌ | ✅ |
| prompts/ | 5 个 | 5 个 |
| references/ | 3 个 | 2 个 |
| examples/ | 1 个 | 1 个 |

IATF 16949 缺少 Hard Gates、证据标准、审计就绪三个段。如果同时加载两个 profile，ISO 9001 的 gate 规则有一部分（如变更控制、文件化信息）对汽车行业也适用，但因为 IATF 没有对称的结构，Agent 的行为会不一致。

#### 7. SKILL.md 里 D 级别的内容和 methodology/dX.md 可能漂移

`SKILL.md` 第 84-148 行复制了每个 D 的核心最佳实践。这些内容在 `methodology/dX.md` 中有更完整的版本。如果后续修改了 methodology 文件，SKILL.md 的摘要可能没跟上。这是一个维护性风险。

### 🟢 P2 — 建议修

#### 8. CHANGELOG 缺少 v0.2.1

v0.2.1 新增了：4 个机制（时间模式/贝叶斯/TRIZ/时限感知）、IATF 16949 profile、quick-ref 卡、ISO 9001 profile、quality-methodologies.md、ISO 9001 hard gates。这些都没有出现在 CHANGELOG 中。

#### 9. SKILL.md "参见" 段不完整

当前只列了 AGENTS.md、usb-no-output.md、gates.md、deliverables.md。缺少：
- `quality-methodologies.md`
- `quick-ref.md`
- `docs/patterns/`
- `profiles/`

#### 10. llms.txt 信息过时

- "56 markdown files" → 实际 ~90
- 没提 profiles
- 没提 quality-methodologies
- 没提 IATF/ISO 9001

#### 11. docs/gates.md 和 docs/deliverables.md 位置

这两个文件在 `docs/` 根目录，但它们是方法论产物。可以考虑移到 `docs/methodology/` 下，保持 `docs/` 根目录只放导航性文件（AGENTS、INTAKE、quick-ref）。

#### 12. Profile SKILL.md 的 YAML frontmatter 字段不完全一致

IATF SKILL.md 有 `metadata.industry` 和 `metadata.standards`。ISO 9001 SKILL.md 也有但结构不完全一致（IATF 用的是 `industry: automotive`，ISO 用的是 `industry: general`）。两个 template 应该标准化。

## 三、Agent 视角的文件加载分析

如果 Agent 按 SKILL.md 的指示启动，实际加载路径是：

```
1. constraints.txt          (2.5KB)
2. docs/AGENTS.md           (15KB)
3. quality-methodologies.md (17KB)
4. [检测到 ISO 9001 → profiles/iso9001/SKILL.md → overlay.md (25KB)]
   [检测到 IATF → profiles/iatf16949/SKILL.md → overlay.md (9KB)]
5. docs/INTAKE.md           (1.8KB)
```

然后每个 D 进入时：
```
6. docs/methodology/dX.md   (5-10KB)
7. 从 docs/prompts/dX-qY.md 中选取（每个 3-8KB，每 D 选 3-5 个）
8. docs/gates.md             (6KB) — gate 检查
9. docs/deliverables.md      (12KB) — 生成交付物
```

**总加载量（无 profile）**：~60KB 的指导文件 + 每 D ~20KB 的 methodology+prompts+gates+deliverables
**总加载量（有 ISO 9001 profile）**：额外 +30KB（overlay + prompts + references）

这是一个合理的加载量——远低于典型上下文限制。但需要注意内容的去重和索引清晰度，避免 Agent 读了 60KB 后仍然不清楚该做什么。

## 五、维持现状的理由（哪些"问题"其实是设计意图）

以下发现可能在第一眼看起来是问题，但其实是合理设计：

1. **SKILL.md 有 D 级别摘要 + methodology/dX.md 有详细版本** — 这是有意的分层。SKILL.md 给 Agent 首次概览，methodology 是执行时的详细参考。保持这一设计，但要确保 SKILL.md 摘要不包含"只在 methodology 里有但 SKILL.md 里漏了"的关键信息。

2. **AGENTS.md 的方向矩阵和 methodology 的方向矩阵** — 不完全重复。AGENTS.md 的矩阵包含"最少覆盖方向数"（如 D4 最少 6 个，必须含 #2/#4/#9），这是 AGENTS.md 独有的执行规则。methodology/dX.md 的矩阵更关注"每个方向怎么追问"。保持两者，但要标注引用关系。

3. **constraints.txt 和 SKILL.md/gates.md 的规则重叠** — constraints.txt 是"Agent 约束"格式（MUST/MUST NOT），面向的是不同 Agent 运行时的兼容性。SKILL.md 和 gates.md 是更详细的操作规则。constraints.txt 适合作为初始约束快速加载，SKILL.md 和 gates.md 是详细执行参考。三层粒度合理，但要内容一致。

4. **两个 profile 的 prompt 数量不同** — IATF 有 5 个（safe-launch, special-chars, csr-check, supplier-8d, ppap-impact），ISO 9001 也有 5 个（risk-thinking, change-control, ncr-control, corrective-action, doc-control）。数量一样，但 ISO 9001 是"每个企业通用"的，IATF 是"汽车特化"的。这个不对称是合理的——两者的行业特化方向不同。

## 六、不改的建议

以下是我看过之后认为不该动的：

1. **不要合并 AGENTS.md 和 quality-methodologies.md** — 它们的职责不同：AGENTS.md 是操作手册（"怎么做"），quality-methodologies.md 是思维框架（"怎么想"）。Agent 需要两个都读。
2. **不要把 prompts/ 合并到 methodology/** — prompt 文件是战术层的（S1-S5 具体话术），methodology 是战略层的（方向矩阵、标杆标准）。分开更清晰。
3. **不要把 profiles 的 overlay.md 拆分** — 当前 overlay.md 包含叠加表+Hard Gates+证据标准+审计就绪，虽然长（ISO 9001 overlay = 25KB），但 Agent 只需要读一个文件就能获得该 profile 的全部 D 级别要求。拆分会增加加载碎片。
4. **不要减少 prompt 文件数量** — 42 个 prompt 是精细化的成本，每个 S1-S5 循环都需要具体的角度和评分标准。合并会降低追问质量。
