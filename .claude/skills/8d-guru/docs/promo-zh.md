8d-guru 就是这个人。一个挂到 AI Agent 上的 8D 调查教练。你给一句话的投诉描述，它用五轮循环带你走完 D0 到 D8：先打开你的思路看没想过的方向，再追到物理层和控制点不让停在表面，然后主动推翻你的结论检验是否扛得住，最后给你的答案打分——不达标不让过。

支持 IATF 16949 和 ISO 9001 行业特化。纯 Markdown，零依赖，任何 Agent 运行时都能挂。

## 中版（产品公告，~500 字）

### 大多数 8D 工具帮你填表，这个帮你找真因

写 8D 的人都有一个时刻——盯着"根因分析"那个文本框，知道写"操作员失误"不对，但手头没有更深的证据。模板不会帮你，它只在乎格式。培训教过方法论，三个月后细节忘差不多了。同事？大家都忙着救别的火。

8d-guru 是一个挂到 AI Agent 上的 8D 教练。你给一句话的投诉描述，Agent 跟你一轮一轮对话，把调查做实。

**它敢反驳你。**

你写"措施：加强培训"，它打断你："培训能解决这个问题吗？能不能让这个失效物理上不可能发生？"

你写"验证：已验证有效"，它反问你："数据呢？样本量多少？量具在有效期内吗？有没有故意放一个故障品测过？"

你写"根因是供应商来料不良"，它继续追："那你的来料检验为什么没检出来？检验项目是谁定的？标准当时怎么选的？"

**不是一个问卷系统，是一个五状态调查循环。**

每个 D 阶段，Agent 带着你在五个状态之间走：先发散打开思路（D4 有 9 个探索方向，Agent 追踪哪些你还没看过），再收敛追到物理层和控制点，然后反事实挑战你的结论，最后给你的答案打 Insufficient/Basic/Excellent 三级——Insufficient 的答案不让往下走。

**三个你可能会用到的机制：**

- **贝叶斯假设追踪**：D4 阶段 Agent 帮你维护候选根因的概率表。每个候选原因有支持证据和反驳证据，概率随调查动态更新。防止你找到一个看似对的答案就停。
- **时间模式检测**：D2 阶段引导你画出不良率的时间曲线。突然跳变的模式和慢慢漂移的模式指向完全不同的根因方向。在进入 D4 之前，先把搜索范围砍掉一大半。
- **TRIZ 8 原理**：当你的纠正措施全部停在"加一道检验"时，Agent 引入不对称、替换机械系统、反馈、颜色/透明度等原理，帮你想到消除级的方案。

**如果你在汽车行业**，Agent 自动加上 IATF 16949 的要求：特殊特性（CC/SC）全链管理、OEM 24h/48h 时限、PPAP 影响评估、Safe Launch 围堵升级、供应商 8D 流延、Red Rabbit 强制验证。

**如果你过了 ISO 9001 认证**，Agent 逐条对 10.2 逻辑链：a) 响应 → b) 判断 → c) 措施 → d) 验证 → e) 风险更新 → f) QMS 变更——六步全闭合才让结案。外审前你心里有数。

纯 Markdown，零 Python，零数据库。任何 Agent 运行时都能挂。

## 要点清单（市场页面 bullet points）

- **主动追问，不被动填表**：每个 D 阶段有 5-12 个探索方向，Agent 追踪你哪些方向还没覆盖，优先带你走没走过的路。
- **追到物理层和控制点**：5-Why 不到三层不让过。"操作员失误""供应商问题""培训不足"被直接拒绝，追到系统控制点才算完。
- **反事实挑战**：你给出重要结论，Agent 主动找反例试图推翻。维护贝叶斯概率表，支持证据和反驳证据同时追踪。
- **答案评分，不达标不让推进**：每个关键回答评 Insufficient / Basic / Excellent。Insufficient 必须补齐。
- **审计就绪**：ISO 9001 和 IATF 16949 各有 20+ 条硬阻断规则、证据标准和审计就绪检查清单。结案前逐项打勾。
- **双版交付物**：每个阶段生成 Basic 和 Excellent 两套报告草案，可直接复制到正式 8D 系统中。
- **行业特化叠加**：支持 IATF 16949（汽车）和 ISO 9001:2015（通用制造业），自动检测行业上下文并加载对应要求。
- **纯 Markdown，零依赖**：挂载即用。Claude Code、Codex、OpenClaw 都能跑。Git diff 直接看区别，fork 后编辑即定制。
- **质量经理速查卡**：可打印的 A4 速查卡，每个 D 的 3 个核心追问 + 3 个禁止答案 + Excellent 标杆。
