## 你缺的不是 8D 模板，是一个敢追问你的人

市面上有几十个 8D 模板、软件、培训。它们都能帮你**填完**一份报告。但填完和做好的区别在于——

你写"根因：操作员失误"，系统照收。8d-guru 追问你："操作员在那一刻看到了什么信息？没看到什么信息？他为什么在那个时刻做了那个决定？"

你写"措施：加强培训"，系统通过。8d-guru 打断你："培训能让这个失效物理上不可能发生吗？能不能改设计或者加防错，让错误根本做不出来？"

你写"验证：已验证有效"，系统结案。8d-guru 反问你："数据呢？样本量多少？量具校准了吗？有没有故意放一个故障品测过你的防错装置？"

**大多数 8D 工具在乎报告格式。8d-guru 在乎你有没有真正找到根因。**

## 挂上 Agent，它会做五件事

### 1. 从你没想过的角度提问

每个 D 阶段有一个探索方向矩阵。D4（根因分析）有 9 个方向：6M 扫描、物理机制、设计假设、控制点回溯、系统交互、时间序列、类似案例、反事实、本体论。Agent 追踪哪些方向你已经覆盖，优先带你走还没看过的路。

你不会漏掉关键视角——因为 Agent 帮你记着。

### 2. 追到物理层和控制点，不让你停在表面

"为什么回流焊温度偏高？"——"因为热电偶换了没校准。"

Agent 不停在这里。它继续追："热电偶更换是维修工单 WO-2406-118。维修流程 MP-007 里为什么没有要求更换传感器后必须重新校准？当初写这份流程时，谁决定不需要这一步的？"

这叫第一性原理收敛。从物理机制 → 设计假设 → 控制回路 → 组织决策，逐层追问。5-Why 停在第二层？Agent 不接受。

### 3. 主动推翻你的结论

你每给出一个重要结论，Agent 会反事实挑战：

"如果这个根因是错的，什么证据能最快证明？"
"有没有一批产品满足同样的条件但没出问题？那怎么解释？"
"如果只修温度不修冷却速率，问题真的会消失吗？"

它还维护一个贝叶斯概率表——每个候选根因有支持证据和反驳证据，概率随调查动态更新。这防止了你最常见的认知偏误：找到一个看起来对的答案就停。

### 4. 给你的答案打分，不达标不让过

每个关键回答被评三级：

| 等级 | 含义 | Agent 做什么 |
|------|------|------------|
| ❌ Insufficient | 模糊、没数据、停在表象 | 指出具体缺口，必须补充 |
| ✅ Basic | 具体、有数据、逻辑完整 | 可以推进，同时告诉你差什么能更好 |
| 🌟 Excellent | 多角度、有证据链、经反事实挑战 | 记录为标杆 |

每个问题点有定制的评分维度（具体性/证据/多角度/深度/可验证性/反面思考）。Insufficient = 不能继续。

### 5. 给你一份审计扛得住的交付物

每个 D 阶段结束时，Agent 生成可复制到正式报告中的草案。Basic 和 Excellent 各一套模板。

如果要过 ISO 9001 或 IATF 16949 审核——Agent 会逐项检查：10.2 逻辑链闭合了吗？8.7 的处置记录完整吗？量具校准证据在吗？PFMEA 更新了吗？每个检查项有明确的通过/阻断标准。

## 它用起来是什么感觉

不是一份干巴巴的模板。是一段这样的对话：

```
Agent: [S1 - 物理机制追问]
"IMC 过厚是温度偏高单独导致的，还是温度+冷却速率共同作用？
如果只修温度不修冷却速率，IMC 厚度能回到正常范围吗？"

你: 我们做了切片。只在温度偏高+冷却偏慢的批次看到 IMC 异常。
温度偏高但冷却正常的批次 IMC 在规格内。

Agent: [S3 - 反事实]
"如果冷却速率正常，即使热电偶没校准、温度偏高，
这个失效还会发生吗？如果不会——你的根因是两个因素的交互，
那纠正措施是不是漏了冷却速率控制？"

...

Agent: [S4 - 评分]
📊 D4 根因分析评分：Excellent 🌟
+ TRC 完整：温度+冷却→IMC过厚→脆化→开裂
+ 物理机制有切片数据（IMC 7-10μm vs 正常 1-3μm）
+ 反事实挑战通过，发现了交互效应
+ MRC 追到维修流程变更管理漏洞
```

完整走查示例：[`docs/examples/usb-no-output.md`](docs/examples/usb-no-output.md)

挂载后 Agent 自动检测你的行业上下文，叠加专属要求。

| 场景 | Agent 追加的能力 |
|------|-----------------|
| **汽车 Tier-1/2 供应商** | PPAP 影响评估、CC/SC 特殊特性全链管理、OEM 24h/48h 时效追踪、Safe Launch 90 天增强围堵、供应商 8D 流延、Red Rabbit 强制验证、Cpk≥1.33/Ppk≥1.67 强制 |
| **ISO 9001 认证企业** | 基于风险的思维（措施不能引入新风险）、变更控制（8.5.6 评审-验证-批准闭环）、不符合输出五种处置路径区分、纠正措施与问题严重度对等性审查、内审和管理评审联动 |

医疗（ISO 13485）、航空航天（AS13100）等行业 profile 计划中。

## 为质量经理设计的小工具

### 贝叶斯假设追踪

D4 阶段，Agent 帮你维护一个候选根因概率表。每条候选原因有支持证据和反驳证据，概率随调查更新。概率 < 40% 继续发散找新线索，40-70% 深度收敛，> 70% 反事实挑战，> 80% 且通过挑战 → 可确认。

**价值**：防止确认偏误——人会不自觉地只找支持自己猜想的证据，Agent 逼你找反驳证据。

### 时间模式检测

D2 阶段，Agent 引导你画出不良率的时间曲线。六种模式——突然跃升、逐渐漂移、间歇性、浴缸曲线、周期性、随机散布——每种指向完全不同的根因方向。突然跃升 → 变更事件，逐渐漂移 → 渐进失效（磨损/漂移），间歇性 → 多因素交互。

**价值**：在进入 D4 之前，先把搜索范围砍掉一大半。

### TRIZ 8 原理速查

当你的纠正措施全部停在"检测级"（加一道检验、加一个传感器）而没有"消除级"的方案时，Agent 引入 8 个质量工程翻译版的 TRIZ 原理——不对称（让错误装不进去）、替换机械系统（用传感器替代人工目检）、反馈（让过程知道自己好不好）、颜色/透明度（让不可见变可见）。

**价值**：帮你跳出"加强检验"的死循环，找到消除级的方案。

### 质量经理速查卡

[`docs/quick-ref.md`](docs/quick-ref.md) — 一张纸。每个 D 的 3 个核心追问、3 个禁止答案、Excellent 标杆、D4 物理层追问话术、D5 TRIZ 速查表、D8 Truth Chain 模板、评分标准、常见跳步阻拦话术。打印贴桌上，不用读 90 个文件就知道 Agent 在帮你追问什么。

## 快速开始

```bash
git clone https://github.com/jilanfang/8d-guru.git
```

挂载到 Claude Code / Codex / OpenClaw 作为 skill。然后：

```
帮我用 8d-guru 调查一个问题：
"客户反馈型号 ABC 的 USB 接口上电无输出。"
```

Agent 会从 Intake 分拣开始，按 D0→D8 引导你走完全程。

纯 Markdown。零 Python、零数据库、零 CLI。任何 Agent 运行时都能挂载。
